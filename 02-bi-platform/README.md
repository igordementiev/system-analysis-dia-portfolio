# BI-платформа по управлению отходами (АИС «ОССиГ» / КИП Платформа)

**Роль:** Аналитик данных

**Домен:** GovTech, Управление городским хозяйством, BI-аналитика, Data Architecture

**Контекст:** Развитие ситуационного центра и аналитической платформы для контроля за перемещением и утилизацией строительных отходов.

## 📝 Описание проекта
Сложная BI-платформа, объединяющая данные о рейсах, разрешениях на перемещение отходов и смарт-контрактах. Система собирает данные из множества источников и предоставляет аналитику через дашборды, а также выявляет аномалии в бизнес-процессах перевозки.

## 🎯 Мои задачи и зона ответственности

### 1. Проектирование отчетности и BI-аналитика
- Разработал требования к дашбордам в **Apache Superset**.
- Спроектировал более 15 витрин данных для отчетности по разрешениям и рейсам.
- Выполнил маппинг атрибутов: описал типы данных, правила трансформации и объединения полей из смежных таблиц БД в витрину.

### 2. Проектирование алгоритмов выявления аномалий
- Разработал алгоритм выявления **«сомнительных рейсов»** (нарушений при перевозке отходов). Описал критерии сомнительности: 
  - несовпадение массы;
  - одновременный выезд с одного объекта;
  - разница во времени менее 60 минут;
  - нахождение на объекте приема менее 4 минут.
- Спроектировал логику интеграции нового алгоритма в модуль расчета корректности рейсов.

### 3. Описание бизнес-процессов и интеграций
- Разработал сквозной бизнес-процесс «Формирование Соглашения о передаче данных с КИП в АИС «ОССиГ»».
- Участвовал в анализе архитектуры данных и оценке интеграционных решений.

### 4. Аудит сторонних инструментов
- Провел аудит и сформировал отчет по внедрению «Конструктора форм» для ЕЦП. 
- Выявил критические ограничения: отсутствие прямого подключения к БД (только Excel), непроработанность интеграции с бэкендом ОССиГ, риски производительности при выгрузке до 20 млн записей.

### 5. Управление требованиями и документацией
- Подготовил полный пакет документации: ЧТЗ, ПМИ, РП, ПЗ, а также детальные спецификации сначала в Confluence, позже переход в Redmine по задачам Jira .
- Провел оценку трудозатрат для задач и сформировал релизные планы.
