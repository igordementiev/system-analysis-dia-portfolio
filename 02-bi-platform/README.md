# BI-платформа по управлению отходами (АИС «ОССиГ» / КИП Платформа)

**Роль:** Системный аналитик
**Домен:** GovTech, Управление городским хозяйством, BI-аналитика, Data Architecture
**Контекст:** Развитие ситуационного центра (СППР) и аналитической платформы для контроля за перемещением и утилизацией строительных отходов.

## 📝 Описание проекта
Сложная BI-платформа, объединяющая данные о рейсах, разрешениях на перемещение отходов и смарт-контрактах. Система собирает данные из множества источников (включая контур КИП) и предоставляет аналитику через дашборды, а также выявляет аномалии в бизнес-процессах перевозки.

## 🎯 Мои задачи и зона ответственности

### 1. Проектирование отчетности и BI-аналитика
- Разработал требования к дашбордам в **Apache Superset** (расчет стоимости, утилизация ресурсов, полные отчеты по рейсам, отчеты по смарт-контрактам).
- Описал логику формирования специфических отчетов на платформе **«Энигма»** (например, вывод списка ответственных за работу с КПТС в рамках контура КИП).
- Спроектировал витрины данных (Data Marts) для отчетности по разрешениям и рейсам (витрины 1062, 1183, 972).
- Выполнил маппинг атрибутов (Source-to-Target mapping): описал типы данных, правила трансформации и объединения полей из смежных таблиц БД (PostgreSQL) в витрину.

### 2. Проектирование алгоритмов выявления аномалий
- Разработал алгоритм выявления **«сомнительных рейсов»** (нарушений при перевозке отходов). Описал критерии сомнительности: 
  - несовпадение массы (±100 кг);
  - одновременный выезд с одного объекта;
  - разница во времени менее 60 минут;
  - нахождение на объекте приема менее 4 минут.
- Спроектировал логику интеграции нового алгоритма в модуль «считалки» (расчета корректности рейсов) платформы «Энигма».

### 3. Описание бизнес-процессов и интеграций
- Разработал сквозной бизнес-процесс «Формирование Соглашения о передаче данных с КИП в АИС «ОССиГ»». Описал роли 10+ участников (ДИТ, ДС, подрядчики), последовательность визирования, формирование протокола интеграционного тестирования и регистрацию объектов в мобильном приложении.
- Участвовал в анализе архитектуры данных (схема с Kafka, Airflow, ODS, DWH) и оценке интеграционных решений.

### 4. Аудит сторонних инструментов
- Провел аудит и сформировал отчет по внедрению «Конструктора форм» для ЕЦП. 
- Выявил критические ограничения: отсутствие прямого подключения к БД (только Excel), непроработанность интеграции с бэкендом ОССиГ, риски производительности при выгрузке до 20 млн записей.

### 5. Управление требованиями и документацией
- Подготовил полный пакет документации: ЧТЗ, ПМИ, РП, ПЗ, а также детальные спецификации в Confluence по задачам Jira (OSSIG-882, OSSIG-972, OSSIG-1751 и др.).
- Провел оценку трудозатрат (PERT-оценки) для задач и сформировал релизные планы.
